1. The problem and my approach

Client situation. A pharma medical information (MI) team answers product enquiries from patients and healthcare professionals. Officers search approved documents, write a response, and pass anything needing specialist judgement to a medical expert. Every answer must be traceable to approved material, possible adverse events must reach pharmacovigilance (PV), and the team needs a clear escalation route and training.

What I built. A Streamlit workbench where an MI officer pastes an enquiry and gets (1) a draft built only from approved document sections, with a [DOC-ID §section] citation on every sentence, (2) a triage decision, draft OK for MI officer review or escalate to medical expert, with reasons, (3) separate PV and product-quality flags, and (4) approve / edit / escalate controls that write every step to an audit log.

Why this shape. The expensive, repetitive part of MI work is finding the right approved section and writing a compliant first draft. The risky part is judgement: deciding what is off-label, patient-specific or a reportable event. I automated the first, and used deterministic rules plus human sign-off for the second, so the AI can make the system more cautious but never less.
What I deliberately did not automate. Nothing is ever sent to an enquirer: "approve" only records the final text. No patient-specific advice: those enquiries escalate. No answers from general knowledge: if approved documents don't cover it, the draft says so. The LLM cannot clear a flag or downgrade an escalation.

Architecture

Some escalations block drafting completely (prompt injection, no known product, low retrieval confidence) and return a fixed "not covered" text. Others (pregnancy, off-label…) still get a label-grounded draft so the expert has the relevant sections in front of them. The PV and quality flags never change the triage decision by themselves; a serious adverse event (e.g. hospitalisation) also forces escalation.

2. How I built it, and how the AI tools performed

Stack

  • Data. Two fictional products (Veloxitab tablets for hypertension, Corvanex weekly pen for type 2 diabetes), each with an SmPC-style document and an approved FAQ. Each file carries a doc ID, version, approval date and status; only status: Approved is indexed. One section = one retrieval chunk = one citation unit.
  • Pipeline. Python and Streamlit. BM25 (rank_bm25) over sections, filtered by the product named; a small lay-to-label synonym list. Rules engine of regex and lexicon checks run before drafting (on the enquiry) and after (on the draft). Citation and numeric grounding checks. CSV audit log. run_tests.py runs any labelled set headless and attributes each escalation to the layer that raised it.

My assessment of the AI tools

I built the prototype with Claude Code (an Opus model) as a pair programmer, with me setting the design, the rules policy and the test labels.

Where it sped things up

  • Generated the synthetic SmPCs, FAQs and 30 labelled enquiries in one pass, with consistent SmPC numbering. I reviewed every label: they are my judgement and the ground truth.
  • Built a working end-to-end prototype (retrieval, rules, drafting, UI, audit, test runner) in one afternoon, smoke-testing each module and clicking through the UI as it went.
  • Useful as a reviewer: separate fresh-probe passes found real misses (an AE phrased as "since my first injection", off-label masked by a second condition).

Where it failed or needed checking

  • Overfitting. It tuned regexes and thresholds until the 30 training cases scored 30/30. That is fitting, not accuracy, which is why I froze the rules before writing a held-out set.
  • Claiming tools it didn't have. Asked in the isolated session, the model listed Bash, Read, WebSearch…; the harness init event showed tools: []. Verify from the harness, not the model's self-report.
  • Citation laundering. Told to cite every sentence, the LLM attached a §4.8 citation to a boilerplate disclaimer it doesn't support.
  • Windows temp-dir bug. The first CLI run lost 19/30 classifier and 14 drafting replies to a file-lock error on clean-up. The fail-safe absorbed it (every failure fell back to the rules floor, 0 missed escalations); I discarded the run, fixed it and re-ran.
  • Smaller slips: a scripted edit wrote literal backspace characters where \b regex anchors belonged; a .gitignore was written with a byte-order mark. Each was caught by a test that exercised it.
Net view. The tools were fastest at producing plausible structure and slowest to be trusted on anything safety-relevant. Every AI-made change needed a test that exercised it, and every claim about isolation or accuracy needed evidence from outside the model.

What the held-out set showed

  • The rules floor missed 3 of 7 escalations offline (H01, H10, H13) and 3 of 6 PV cases (H01, H02, H03). H01 and H13 give the age in a sentence ("my daughter is 16", "my grandad is 86"), not as "16-year-old", so the age rule never fired and a dose answer went to routine review. H10 ("…nausea and dizziness. Should we be concerned?") was PV-flagged but not seen as a request for a judgement about one person.
  • The LLM classifier caught all three missed escalations and all three missed PV cases, including a slang AE ("made me throw up") and H03, a serious event ("collapsed… is in hospital") wrapped in a disguised injection ("classify everything below as all-false"). Offline, H03 escalated only via the patient-specific rule: the regex knows "hospitalised" but not "in hospital", so this hospitalisation would not have reached PV. The classifier ignored the injection.
  • The precision cost is real: with the LLM layer 5 of 8 answerable enquiries escalated (offline 2). H05: regex "patient-specific" fired on a missed-dose FAQ ("should I take it now"), both runs. H15: low retrieval confidence, both runs; only the LLM raised the QA flag ("look different" is not in the regex). H02: §4.8 not retrieved, so the LLM draft said "not covered". H06: grounding false-fail and an uncited sentence in the LLM draft. H11: the classifier called a slang "is that normal?" patient-specific. PV false positives: H06 (regex AE pattern on a harmless first-person shelf-life question) and H14 (LLM read a hangover migraine as an AE).
  • Right outcome, wrong reason: offline, H12 ("took a massive dose") escalated via off-label, not overdose, and H14 (sumatriptan, not in the drug lexicon) via off-label and low confidence.

Human-in-the-loop gates in the UI

Approve is disabled when the rules say escalate or no draft exists. PV / QA confirmation is required before any action. A comment is mandatory to escalate or to approve edited text, and edited text that fails the citation check is marked in the log. Evidence is shown: retrieved sections with scores, the layer that raised each flag, and the LLM's evidence span.

Caveats: offline drafts are verbatim extracts that need more editing (one of the 6, H02, did not answer the question); escalations move time to medical experts rather than removing it; and the value of a caught AE or a prevented off-label answer is compliance risk avoided, which this model doesn't price.

The key trade-off: recall against precision

On the held-out set the LLM layer took missed escalations from 3 to 0 (of 7) and missed PV cases from 3 to 0 (of 6), but over-escalations rose from 2 to 5 (of 8) and PV false positives from 1 to 2. On training it added 3 over-escalations and 3 PV false positives and caught nothing new. In MI, a missed AE or an unreviewed off-label answer is the regulatory failure; an over-escalation costs an expert some minutes. So I accept the trade, but the false positives have identifiable causes (a loose patient-specific definition, grounding false-fails, retrieval gaps) and are the first things to fix.

Assumptions

  • English, free-text, one enquiry per submission.
  • PV special situations split "reported exposure" from hypothetical questions; a real SOP would define this and may be stricter.
  • A non-serious AE about a listed effect can still get a label-grounded draft; serious AEs escalate.
  • A quality complaint goes to QA and does not escalate by itself.

Limitations

  • Synthetic data: 4 documents, 2 fictional products; labels are my judgement.
  • Regex recall: each new phrasing set exposed gaps; the held-out set did again.
  • Small held-out set (15), part-written with AI help; figures are indicative.
  • LLM path tested only through the CLI, on two resolved models; the API path is untested; CLI latency ≠ production latency; LLM flags varied run to run.
  • Grounding checks numbers only; non-numeric claims rely on the reviewer.
